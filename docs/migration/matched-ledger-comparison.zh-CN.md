# 合成账本对照

[English page](matched-ledger-comparison.md)

现有 Python 执行模拟器与独立 Rust 引擎在下面这个两日合成案例中，得到相同的订单状态、成交金额和每日财务数值。Python 的数量根据成交金额和案例价格推算。这份结果覆盖一个小范围。迁移实际调用方时，仍需核对它的数据和交易规则。

`scripts/benchmarks/compare_engine_ledgers.py` 会实际运行两边。Python 通过 `simulate_execution_adjusted_nav` 把目标权重转换成订单。Rust 通过独立 SDK 接收明确的市价单数量，再交给 NautilusTrader 成交和记账。脚本只把结果转成可比较的字段。

## 两边使用的假设

账户初始资金为人民币 10,000 元，只交易合成标的 AAA。两边均使用原始价格，买入每手 100 股，开启 T+1。首日目标权重为 10%，次日降到零。

Python 每天用同一个价格成交和估值。Rust 请求因此在开盘和估值时各放一条买卖价相同的报价，两条报价价格也相同。报价数量和每日成交容量都足够大，两笔订单可以全部成交。这些报价专门为实验生成，工具不会把历史 OHLCV 日线转换成可执行报价。

两边的佣金均为 10 个基点，即成交额的 0.1%，没有最低佣金。印花税、过户费和滑点均设为零。Python 通过 `DetailedTradeFeeModel` 明确设置这些费用，`transaction_cost_bps` 保持为零。后一个选项还会在规划目标金额时预留费用，影响买入数量。这里使用单独的费用模型，让 Python 首笔订单金额保持为 1,000 元，与 Rust 买入 100 股的请求对应。

| 交易及估值日 | 数量与价格 | 佣金 | 现金 | 持仓市值 | 净值 |
| --- | --- | --- | --- | --- | --- |
| 2025-01-02 | 以 10 元买入 100 股 | 1 | 8,999 | 1,000 | 9,999 |
| 2025-01-03 | 以 12 元卖出 100 股 | 1.2 | 10,197.8 | 0 | 10,197.8 |

## 脚本核对什么

脚本逐笔比较订单的标的、方向、日期、推算成交数量和最终状态。比较成交记录时，Python 一边使用案例价格和推算数量，Rust 一边使用引擎实际返回的价格和数量，同时核对佣金。每日账目核对现金、推算持股数量、持仓市值、佣金和净值。报告保留两边的原始结果，也列出转换后的表格。

旧模拟器的成交记录使用成交金额，本案例没有独立的成交价格字段和持股数量账本。这里只有一个标的，每天价格已经明确，所以脚本用成交金额除以当天价格推算数量，再根据买卖方向累加每日持股数量。报告的 `python_derived_fields` 字段记录了这些假设。这一步只适用于本案例，不能直接拿去处理多价格成交或公司行为。

数值比较使用固定绝对误差 `0.00000001`，容纳 Python 浮点运算产生的小误差。引擎的十进制金额在比较时继续保留十进制精度。日期、订单状态和行数必须完全相同。任何字段对不上，命令都会以退出码 1 结束。

一项回归测试只把 Rust 首日估值报价从 10 元改为 11 元。首日持仓市值和净值因此各多 100 元，最后净值仍为 10,197.8 元。脚本能找到这两处每日差异。仅比较最终收益会漏掉它们。

## 怎样复现

先安装锁定的开发依赖，再选择一个不可变的引擎程序。传入摘要前，要先用所选构建记录核对程序文件。

```sh
uv sync --locked --all-groups
uv run --locked python scripts/benchmarks/compare_engine_ledgers.py \
  --engine-executable /releases/engine/quant-backtest-engine \
  --engine-sha256 <verified-executable-sha256> \
  --engine-source-revision <full-engine-source-revision> \
  > /data/quant-platform/tasks/ledger-comparison.json
```

输出目录需要提前建好，放在源码仓库之外。SDK 会在运行前核对程序字节摘要。源码提交单独记录，用来追溯构建来源。

CI 的 `engine-sessions` 任务会构建 `.github/workflows/ci.yml` 固定的引擎版本，再用真实程序运行 `tests/test_engine_ledger_comparison.py`。本地集成测试通过 `SESSION_ENGINE_BINARY` 和 `SESSION_ENGINE_SHA256` 选择程序。没有这两个变量时，两项真实引擎测试会跳过，Python 和比较逻辑的回归测试继续运行。

## 这份结果能说明多少

本案例按交易日核对财务数值。Python 审计字段只有日期，Rust 请求给出了明确的日内时间，两边的时间信息仍有差别。实验没有验证日内时间完全一致，也没有证明输入在当时已经可用。

两笔订单均全部成交。虽然开启了 T+1，本案例没有尝试当日卖出。部分成交、订单跨日保留、公司行为和分日期税费还需要各自的对照案例。每日成交金额容量与报价数量也是两种模型，只是在这里都没有限制成交。

只有目标权重和 OHLCV 日线的调用方，需要先写明转换规则，再检查数据可用时间，才能评估报价回放引擎。通过这些检查和[删除条件](portfolio-boundaries.md#final-removal-gates)前，继续保留它的 Python 流程。
