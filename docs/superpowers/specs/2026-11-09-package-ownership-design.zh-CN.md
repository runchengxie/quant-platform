# 回测拆分后的包归属整理

[English](2026-11-09-package-ownership-design.md)

状态：用户于 2026-11-09 要求实施按职责拆分的建议。本文记录实施默认选择和兼容门禁，既有 Engine 与日报发布任务继续推进。代码迁移不授权券商连接、下单、生产切换、真实训练或数据获取。

## 交付目标

Platform 保留通用组合、风险、分析机制和明确的消费适配。模型、回测账户、跨项目流程及通用订单生命周期各自有独立 owner 和安装验收。代码、测试、文档、调用方及历史恢复路径一致，才算迁移完成。

撮合、回放、模拟账户等仍由既有 Engine 计划实施，不在这项整理中重复搬迁或改写算法。

## 依据和方案

Platform 7a618bd 的只读清单包含 35 个 microstructure Python 文件、33 个 orchestration 文件和 69 个 execution 文件，共约 2.7 万行源码（含注释/空行）。与 Deep Learning 同路径的 26 个文件中只有 5 个字节一致，需要核对 API、数据和检查点协议。静态导入命中 275 个文件，含内部实现及测试，不能当作生产部署清单。

| 方案 | 取舍 | 选择 |
| --- | --- | --- |
| 三个目录整体移到三个名称相似的仓库 | 初期省事，但会把训练移入 worker、把券商服务移入回测器 | 不采用 |
| 实现留在 Platform，仅换入口 | 耦合与命名空间重复依然存在 | 仅作冻结的旧版恢复路线 |
| 按完整职责迁移，先发布提供方再切调用方 | 兼容工作较多，但能独立安装并验证 | 用户要求实施的方向 |

真实券商适配已在私有执行 owner。公开 Platform 主要是通用接口、订单状态服务、离线 mock 和工厂入口；不能借迁移把私有适配、凭据或策略配置公开。

新通用库的实施默认名称暂定 quant-trade-execution，分发名相同，规范命名空间 quant_trade_execution，首版 0.1.0。这是实施者提出的默认值，不代表已有部署仓库或用户明确指定拼写。创建前核对用户仓库，仅使用已有公开代码；不复活已退役旧检出，也不为改名新增真实下单 CLI。

## microstructure 与模型收敛

Deep Learning 是训练代码的规范 owner。逐文件核对公共符号、输入/检查点 schema、功能差异及调用方；保留规范仓库现有工作，并通过审阅把 Platform 独有的有用改动补进去，不能用旧副本覆盖新实现。

模型、权重形状、标签、切分、时钟和预测 artifact 保持原义。旧结果/检查点保留实际 producer、源码和依赖身份；schema 名相同不等于兼容。不支持的旧检查点保留完整固定旧环境，不改写历史元数据。

Deep Learning 声明 Python 3.10+，Platform 有部分 3.12 专用设施。优先使用兼容导入/注解，并真实验证相关 3.10 路径及现有 CI；必要的支持范围调整必须明确并独立验证。所有权迁移不产生新的训练或实证结论。

先合入 Engine 的独立模拟/原生撮合提供方，再切新调用方。Engine/Platform 基础导入不带入训练依赖；原生撮合不是 Nautilus，保留独立身份和许可。

## 每个安装文件只有一个 owner

同时审计 wheel RECORD 和 console entry point。

- Deep Learning 拥有 ticknet 根、模型、数据集和 eventstream；可提供按需加载的 ticknet.simulator 兼容薄层，显式依赖已合入的 Engine。调用方迁移后 Platform 不再打包 ticknet 文件；Engine 独立撮合仍不需要 Torch。
- Task Orchestrator 拥有规范协调 API 及轻量 strategy_pipeline 根/control_plane 兼容薄层，不 import 私有 Research，也不自动批准持久工作流。Research 的显式研究安装可提供不重叠的 strategy_pipeline.pipeline 子模块。核验每个文件唯一归属、父子包发现和依赖/卸载行为。
- 旧 strategy-pipeline 训练 CLI 切换后由 Research 提供；Platform 停止注册，通用工作流使用 quant-task。公开 Platform 不声明私有依赖。已知训练调用方先迁移，公开用户保留明确固定旧版路线。
- 新执行分发同时拥有规范 quant_trade_execution 和薄 quant_execution_engine 别名；Platform 不再打包旧文件，改消费合入的提供方。别名类必须是同一个对象。Engine 金融别名仍遵守现有计划。
- 支持的别名至少保留两个 minor 周期，且所有登记调用方完成迁移或有固定旧环境后才退休。文件提供方变更但导入路径继续有效，不等于提前删除 API。

Research 目前也注册了部分规范模型 CLI 名称。迁移时将私有专用入口改为明确的研究入口并迁移调用方，规范模型命令仅由 Deep Learning 提供；不把私有模型差异搬到公开仓库。旧定制命令保留完整固定旧安装路线，不能靠安装先后决定执行哪份代码。

不得由两个 wheel 覆盖同一模块或 CLI。完整非 editable 安装组合要证明文件、导入、类身份和依赖闭包。

## 研究流程与编排

研究决策和策略流程归 Research；通用日期/统计/组合原语仍可调用 Platform API，不向公开编排器复制私有策略。

真正通用的 RunOwner/ArtifactPublisher 协调归 Task Orchestrator，不能削弱已有计划摘要批准和审计。无状态兼容 helper 不隐含持久研究任务的批准。

Runtime 保留回测执行职责，不接收训练、选模、报告或晋升。跨 owner 使用已审阅的安装 API/CLI 或版本化 artifact，不能用源码路径或私有 import 冒充复用接口。

私有调用方路径、策略参数和试验记录仅留在私有清单/Research 文档；公开迁移表只记录角色和公共 API。代码迁移不重跑或重置研究试验。

## 通用交易执行库

迁移完整公开 OMS/模型/序列化/风控/状态/对账/facade/mock 闭包，保留数值、排序、订单/账户身份、幂等、预留、kill switch、撤单、恢复及完整 trace/state，并记录原 Apache 来源。

Alpaca/IBKR/Longport 实现仍归私有 owner。公开提供方只声明真实实现的能力，缺少 provider 明确报错；可信本地调用方可显式注入类型一致的 adapter。请求不能指定任意 import/命令，假 SDK 不能冒充真实支持。

mock 是离线 OMS 测试对端，不能证明真实券商或经校准回测。Engine 保留量化模拟 owner，同一运行不能出现两份现金账。

基础导入不加载私有 Research、训练、Runtime 或网络客户端，不创建状态目录或探测账户。小型配置/渲染依赖明确声明。核对既有 QEXEC/配置/输出设置和源码相对路径兼容性，不能换路径悄悄建空账户。新应用显式指定仓库外根；旧状态在独立授权、验证的运维交接前原地保留。

旧回执保留原 producer，包括未知值。不伪造历史源码摘要，不承诺搬迁后热恢复；切调用方前验证完整离线生命周期、序列化、失败/重启及私有 provider 注入。

## 文档与可用状态

每项迁移均保留原许可、版权和逐文件来源，包括移入默认许可不同仓库的模型及编排代码；原许可文本进入实际 wheel，元数据反映真实组合，不静默改许可。

代码、测试、双语安装/API/能力说明、源码历史和迁移表一起交付。提供方合入后才把旧 URL/锚点改为语言正确的薄跳转，不把计划写成已发布。

公开登记区分 planned/implemented、真实审阅源码、发布可用状态及可执行验收，无占位/自引用 SHA 或私有调用路径。按实际依赖分别提交 provider PR，再切 Platform 消费方，并同步相关项目的边界文档和安装示例。

## 实施和恢复顺序

1. 冻结清单/预期值，完成现有 Engine 及 Platform 对应模拟/账户批次。
2. 收敛、发布 Deep Learning 模型 API/检查点说明及 Engine 模拟兼容层，验证 ticknet 无重叠。
3. 发布通用编排 API/旧根，再切私有 Research 流程/CLI，完成合成研究验收。
4. 从公开代码发布独立通用执行库，再接私有 adapter 注入和 Platform 旧导入。
5. 各 provider 合入、完整安装组合通过后，移除 Platform 的实质实现/重复 CLI/文件；保留别名及固定旧环境。
6. 核对共同 main 版本、语言路由、文档与清理，只处理本任务资源。

每个 owner 独立 worktree/分支、跑自身门禁，记录共同验证的版本。保留无关/生产 worktree 和历史数据；既有合并授权继续有效，另行授权的生产操作等具体方案完成后再处理。

## 验收

- wheel/入口无重叠，公开提供方无反向私有/训练依赖，离开源码独立安装可运行。
- 模型/API/协议及相关 Python 版本回归保留原证据边界，旧检查点明确拒绝或固定旧版。
- 编排批准/审计、Runtime 持久任务职责不减弱，研究记录不变。
- 通用执行公式、序列化、幂等、离线 trace/state 一致，缺失 provider 明确，测试无网络下单。
- 登记调用方验证或固定旧版，别名/文档路由保留，公开清单无私有路径。
- 各 owner 完整门禁和共同版本独立审阅通过后合并；真实训练、凭据、订单、生产迁移或删除归档都不能作为验收捷径。
